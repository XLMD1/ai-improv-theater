# AI 即兴剧场：分阶段开发与验收

版本：v0.1
对应文档：[需求](01-requirements.md) · [技术设计](02-technical-design.md)

## 工作方式

每阶段先对照需求和技术设计确认边界，再实现、运行该阶段测试、提交。Commit 标题统一为 `English: 中文`，例如 `docs: 建立需求与技术设计`、`feat: 实现分支存档`、`test: 覆盖中断恢复`。未经过验证的代码不标记完成。

三文档建立前的模型、记忆和 Docker 草稿仍留在本地，未进入阶段 1 提交。它们不能视为通过测试、可部署或可写进简历的成品。

## 阶段 0：文档基线

- [x] 写清产品范围、玩家流程、验收标准与不做事项。
- [x] 写清生成协议、事实优先级、分支数据、SSE 与恢复策略。
- [x] 划分阶段门槛和 commit 格式。
- [x] 确认 GitHub 目标仓库并上传文档提交。

验收：三份文档互相引用，范围一致；GitHub 上可查看初始文档提交。

## 阶段 1（第 1–2 周）：状态机与可回放底座

- [x] 完成迁移与本地 PostgreSQL 初始化；验证结构与 ORM 一致。
- [x] 实现固定五场景、三结局的合法转移及状态变更约束。
- [x] 实现会话、节点、不可变事件、分支树与原样回放。
- [x] 前端完成第一幕、选项、回退、分支查看和关系显示。

验收：不用真实 LLM，也能从初始节点走到三个结局；旧节点文本与状态在回放时完全相同。非法场景、越权 flag、分支隔离和回放测试通过。

本地验证记录：隔离 PostgreSQL 18 数据库上执行 `alembic upgrade head` 与 `alembic check`，后者报告无 ORM 结构差异；`pytest` 6 项通过；前端 `npm run typecheck` 与 `npm run build` 通过。浏览器实际验证了首幕、选择、回退与第二分支，两个同场景分支的关系值不同。阶段 1 未验证真实模型、pgvector 和生产部署。

复现时，在独立的 PostgreSQL 测试库（名称以 `_test` 结尾）设置 `DATABASE_URL` 和 `MIGRATION_DATABASE_URL`，进入 `backend/` 安装 `.[test]` 后执行 `python -m alembic upgrade head`、`python -m alembic check`、`python -m pytest -q`。进入 `frontend/` 执行 `npm ci`、`npm run typecheck`、`npm run build`。运行页面时后端使用相同数据库 URL 启动 `uvicorn app.main:app`，前端执行 `npm run dev`。无需任何模型密钥。

## 阶段 2（第 3–4 周）：单次生成基线

- [ ] 接通一种真实聊天模型；固定模型和 prompt 版本。
- [ ] 实现单次生成、严格 JSON 校验、状态提交和安全过渡幕。
- [ ] 实现任务幂等、阶段事件、批准后文字分块、断线补发。
- [ ] 加入实际 token 用量与费用估算，限制单会话与全站预算。

验收：真实模型可稳定完成一局；同一幂等键只产生一个节点；断线后能恢复同一 run，审核前不泄露正文。

## 阶段 3（第 5–6 周）：多 Agent 与长期记忆

- [ ] 导演、编剧、出场角色、审核各按严格协议调用；修复最多一次。
- [ ] 只写入已批准的重要记忆；按祖先链、过期和最新 `fact_key` 检索。
- [ ] 角色卡落实目标、禁忌和行为值；加入 12 情境 × 5 次的人格评测集。

验收：多 Agent 与单次方案使用同一状态校验和存档接口；旧分支记忆不会进入另一分支；审核误报不能覆盖事实。

## 阶段 4（第 7 周）：比较实验

- [ ] 固定 40 个情境：正常推进 20、角色冲突 10、记忆或分支干扰 10。
- [ ] 每情境各方案运行 3 次，匿名打乱，双人盲评并记录分歧。
- [ ] 计算一致率、角色一致率、可玩性、p95 时延和实际费用。

验收：评测原始结果可追溯；README/简历只陈述有证据支持的改善。

## 阶段 5（第 8 周）：上线与展示

- [ ] Vercel 静态前端、Fly API、Neon 数据库部署并配置生产域名 CORS。
- [ ] 从生产域名走完五幕，验证三个结局和一次断线恢复。
- [ ] 完成 README、架构图、演示录屏、部署与故障排查说明。

验收：匿名访客无需本地环境即可体验；无密钥泄漏；在线演示与文档中的功能一致。

## 最高优先级的十项测试

1. 缺字段或多字段的 Agent 输出被拒，且无节点。
2. 非法场景转移被拒。
3. 越权状态键不改变快照。
4. 事实冲突触发至多一次修复，随后使用安全过渡幕。
5. 审核引用不存在的事实键不产生否决权。
6. 同父节点两分支的状态与记忆隔离。
7. 修改模型/prompt 后旧节点仍原样回放。
8. 失效记忆、跨分支记忆不会被召回。
9. 并发提交同一幂等键只创建一个 run 与节点。
10. SSE 断线补发不重不漏；重启未提交任务无幽灵节点。
