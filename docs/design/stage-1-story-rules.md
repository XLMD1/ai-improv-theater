## 1. 范围与成功条件

阶段 1 交付纯规则底座：严格故事协议、调查快照、声明式条件/效果、确定性裁决、可达性校验、新旧版本分派，以及可复现的最小任务成功率评测。自定义故事模型生成、真实外部调用执行器、图片、完整新前端和多 Agent 分别在后续阶段接入。

首版固定三位角色（含玩家主角）、五个主要地点、三个不同后果结局。调查目标约 15–25 次有效行动；无硬倒计时。有效行动和地点切换分开，同地点调查合法；重复、无效及条件不成立的行动不发放证据、不改变地点。旧 Demo 的五场景推进协议保留，不能套用新调查规则改写旧节点。

## 2. 故事协议

使用禁止额外字段的 Pydantic 模型，枚举使用 Literal/判别联合，数值字段严格区分整数和布尔值。实体 ID 是 1–64 字符的 `[a-z][a-z0-9_]*`，不接受文件路径、脚本或模型创建的新操作名。列表不允许重复 ID；所有引用必须指向同一故事版本。

| 字段 | 类型与约束 | 用途 |
|---|---|---|
| `schema_version` | 固定 `investigation-story-1` | 故事协议版本 |
| `story_id` / `story_version` | UUID / 1–30 字符版本标识 | 不可变设定的身份；不同版本不混用 |
| `title` / `setting` / `era` / `public_intro` | 非空文本 | 背景、年代、无剧透简介 |
| `protagonist_id` / `start_location_id` | 合法角色/地点引用 | 玩家身份、初始地点 |
| `characters` | 恰好三张角色卡 | 名称、目标、禁忌、外貌、初始地点、已知事实 ID、秘密事实 ID |
| `locations` | 恰好五个地点 | 名称、公开描述、带条件的有向出口 |
| `objects` | ID、地点 ID、公开名称及调查描述 | 可调查对象，不直接携带隐藏证据 |
| `evidence` | ID、发现后描述、支持的真相事实 ID | 证据定义，发现条件来自规则 |
| `truth` | 固定真相文本与 `facts`（事实 ID → 文本） | 服务端私有；角色知识/秘密引用这里的事实 |
| `disclosures` / `commitments` | ID → 定义 | 可记录的披露及承诺，效果不得创造未声明 ID |
| `action_rules` | 调查/交流/出示证据的匹配、条件、效果、反馈 | 玩家行动的确定性裁决 |
| `events` | 条件、效果、公开反馈；每个事件只触发一次 | 角色主动行为 |
| `endings` | 恰好三个：ID、条件、公开标题及后果 | 只能由玩家最终抉择进入 |

规则记录固定为 `ActionRule(id, action, conditions, effects, once, feedback)`，`action` 使用第 4 节的调查/交流/出示判别联合精确匹配；移动出口为 `Exit(location_id, conditions)`，主动事件为 `Event(id, conditions, effects, feedback)`，结局为 `Ending(id, conditions, title, consequence)`。`conditions`、`effects` 使用第 3 节的判别联合，`feedback` 为可公开非空文本。出口与结局不重复注册成行动规则，未知字段或操作拒绝。

披露定义包含所属角色、已声明事实 ID 列表和公开文本，承诺定义包含所属角色及公开承诺文本；证据的事实支撑引用用于内部校验，不直接输出给玩家。公开投影仅依据已发现/已披露状态返回公开文本，不因可猜测的事实 ID 或支持关系提前揭示真相。

角色知识不等于玩家知识；未公开事实不能因角色卡、对象或证据名称进入浏览器。公开投影只输出无剧透设定及当前已披露/发现内容。设定批准后保存其版本和规范化 JSON 的 SHA-256，不再修改真相、规则或证据；后续改稿产生新版本，不更新旧版本。

## 3. 声明式条件与效果

条件为有限原子条件的 `all` 列表，空列表表示真。首版不加入嵌套表达式、任意函数、时间条件或可执行代码；需要 OR 时写成分别可达的规则，并检查匹配冲突。

| 条件操作 | 参数 | 判定 |
|---|---|---|
| `at_location` | `location_id` | 当前地点相同 |
| `has_evidence` | `evidence_id`, `expected: bool` | 已发现集合是否包含 |
| `has_disclosure` | `disclosure_id`, `expected: bool` | 已披露集合是否包含 |
| `has_commitment` | `commitment_id`, `expected: bool` | 已承诺集合是否包含 |
| `event_fired` | `event_id`, `expected: bool` | 主动事件是否已发生 |
| `trust_at_least` | 非主角 `character_id`, `value: int[-3,3]` | 角色对主角信任达到阈值 |

效果仅允许 `discover_evidence(evidence_id)`、`disclose(disclosure_id)`、`record_commitment(commitment_id)`、`trust_delta(character_id, value: int[-2,2])`。效果引用白名单实体；信任结果必须在 -3..3 内，越界拒绝整个裁决，不截断或部分应用。包含信任变化的行动规则必须 `once=true`，防止刷同一行动；其他规则明确声明是否一次性，重复发现不产生第二份证据。主动事件全部一次性。

移动只通过当前地点的合法出口并检查其条件；地点不由模型提出的状态效果任意赋值。结局只通过 `decide` 检查指定结局条件设置，行动规则和主动事件不能隐式结束游戏。依赖图来自条件及效果引用，但是否能发现证据最终由实际状态搜索验证，不能仅凭“依赖图无环”判定可玩。

## 4. 调查状态与行动协议

新快照为 `schema_version=2`、`engine_version=investigation-1`、固定 `story_id/story_version`、`location_id`、`action_turn`、`discovered_evidence`、`disclosures`、`commitments`、`trust`、`applied_once_rules`、`fired_events` 和可空 `ending_id`。集合保存为排序列表以保证稳定序列化；信任只包含该局非主角角色，初始为 0。每个新分支从父快照复制，不能共享可变集合。

首版角色位置使用设定中的初始地点，不新增角色自动迁移效果；主动行为限于已声明的披露、承诺及信任/证据效果。玩家发现的证据和披露属于分支状态，角色私有知识不直接复制到玩家已知集合。

内部行动是判别联合，禁止额外字段：

| `type` | 必需字段 | 基础约束 |
|---|---|---|
| `investigate` | `object_id` | 对象属于当前地点 |
| `talk` | `character_id`, `topic_id` | 角色在当前地点，话题属于该角色已声明规则 |
| `present` | `character_id`, `evidence_id` | 角色在当前地点，证据已发现 |
| `move` | `location_id` | 出口存在且条件成立，不能移动到原地点 |
| `decide` | `ending_id` | 结局存在、条件成立、尚未结束 |

现有外部 `Action(type=option|text, value<=500 字)` 不改其旧含义。阶段 2 把按钮或自由输入解析为上述内部行动，模型只提出行动解释。阶段 1 使用已规范化行动测试规则，不把自由文本理解能力写成已完成。

裁决返回 `status=accepted|invalid|repeat|precondition_failed`、反馈代码、服务端确定的效果与可公开反馈。不合法的 schema 返回独立 validation 错误。被拒绝/重复行动的快照与父状态完全一致，不增加 `action_turn`、不触发主动事件；阶段 2 可保存反馈节点，但不能伪造进度。有效行动成功才增加一次回合，移动是有效行动的一种；回合数不参与结束或事件条件。

## 5. 裁决和唯一更新路径

1. 校验故事/引擎版本、父快照引用和行动结构；终局拒绝继续。
2. 校验目标、地点、已知证据和规则条件。零个匹配返回条件不成立；多个可适用匹配为故事规则冲突，拒绝提交，不由模型任选。
3. 在父状态副本上计算行动结果；一次性规则已使用则返回重复。任何非法效果令整个结果失败。
4. 在有效行动结果上检查主动事件，按事件 ID 排序逐个应用，已触发事件不重发；重复检查直到没有新增事件，最多处理事件总数次，不运行模型自主循环。
5. 通过现有 `app/state.py` 的统一状态更新路径重新校验服务端效果后返回新快照；生成器与审核无数据库写权限。
6. 在后续任务路径中，批准渲染、状态、节点和事件单事务提交；候选稿不能进入 SSE。规则异常保留父快照。

阶段 1 模块边界：故事 schema/校验器接收 JSON 返回验证后的故事；裁决器接收故事、父快照及规范化行动返回裁决；统一状态更新路径验证并应用裁决；公开投影接收故事及快照返回玩家可知信息。普通内部函数无需注册为模型工具；模型/外部调用注册协议见[运行可靠性设计](runtime-reliability.md)。

## 6. 校验和可达性证明

先检查数量、唯一 ID、全部引用、效果白名单、角色/对象地点和结局条件。再从初始快照执行有限状态广度搜索：枚举当前可调查对象、已声明话题、已发现证据出示、合法出口及三个结局抉择，用同一个裁决器和统一状态更新路径得到后继。拒绝/重复的无变化结果不扩展；终局不继续扩展。

去重键包含地点、证据、披露、承诺、信任、一次性规则和事件集合及结局，排除回合数与展示文本；协议禁止依赖回合条件，所以不会隐藏有意义的状态差异。每个事实集合有限、信任有界、主动事件一次性，因此搜索空间有限。默认最多检查 50,000 个唯一状态，超限返回 `reachability_inconclusive` 并拒绝批准，不冒充“不可达”或“通过”。

通过条件：五个地点至少各有一条实际合法到达路径；每项声明证据至少有一条发现路径；三个结局各有完整见证行动序列；所有可达状态没有多规则匹配冲突。发现断路、证据互锁、非法效果或不可达结局时输出具体实体/规则 ID 和失败原因。见证序列保存到阶段 1 固定样本供回归；搜索不调用模型、不写故事数据库。

语义检查不能由图搜索替代。阶段 1 对人工样本使用“事实 → 支撑证据 → 推理是否充分 → 是否依赖未提供信息”的审定表；阶段 2 自定义创建再接入受控语义检查与至多一次设定修复。结构通过、语义未通过的故事不能批准。

## 7. 旧引擎与持久化兼容

现有旧 `schema_version=1`、`scene_id`、flags、relations、结局 ID 和 `canon.json` 不改含义。旧 `apply_state_changes(parent_state, scene_id, changes)` 调用保持兼容；统一入口根据明确引擎版本分派新规则，缺少新元数据的旧会话走 legacy，未知版本返回错误而非猜测。新分派扩展只在该统一路径内，不能绕开它另写数据库状态。

阶段 1 增量迁移保存不可变故事版本，并为会话增加可空故事/引擎/模式标识，为节点增加可空版本关联；旧记录保持原值，不重写快照或批准渲染。新故事默认版本仅用于新建记录，不能用 SQL 默认/批量回填把旧会话解释成新引擎。角色/地点 ID 字段支持 64 字符，旧短 ID 保持可读。详细 ORM 迁移应与实际 schema 同一任务验证，不在本文添加未验证迁移代码。

固定样本不修改正在使用的 `canon.json`，也不替换现有 Demo。用户审定后，新调查样本作为独立版本/测试 fixture；旧节点始终读取保存内容。回放不执行裁决器、生成器或外部工具，不受新版本规则、模型、prompt 改变影响。

## 8. 雾港样本交付规格

沿用林岚、周砚、沈知夏三位角色，林岚为玩家主角；主要地点保留候船厅、旧档案室、码头、钟楼、灯塔。新样本使用独立故事版本及可读 ID，不把旧 `c1/s1` 当新故事硬编码。

阶段 1 起草样本时必须同时提交完整固定真相、角色知识/秘密、每个对象与话题、证据发现规则、主动事件和三个结局条件，不能只填标题、占位文本或无条件结局。结局保留“公开真相／共同守护／秘密沉海”的主题，但各自证据与后果要由用户审定；本次文档整理未起草或批准这份剧情。

审定材料包含：三角色与五地点清单、证据如何支撑固定真相的表、三个结局的实际见证序列及后果比较、重复/非法行动反馈、15–25 次有效行动目标的路径统计。真实游玩时长需后续试玩，不能从行动数直接推算。用户审定前样本标为 draft，自动校验通过也不等于人工批准。

## 9. 验证门槛

单元测试覆盖额外字段、错误类型、未知版本、越权引用、非法效果、重复/无效行动、同地点多轮、信任越界、主动事件一次性、证据互锁、结局不可达、搜索超限及分支父状态不被修改。集成测试在独立测试库验证增量迁移与旧节点/事件/渲染原样回放、版本隔离及玩家公开投影。

阶段 1 还必须提供 `evals/run_stage1.py` 最小评测入口与固定案例清单，输出任务成功率和失败明细，具体口径见[基础任务评测](../evaluation/task-success-baseline.md)。这些路径是后续实现交付项，本次不创建空脚本或声称测试已通过。
