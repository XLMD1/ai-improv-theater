## 1. 当前基线与阶段分工

当前 `provider_clients.py` 集中供应商 HTTP，配置 20 秒超时并转换 HTTP/响应错误；`generation.py` 校验候选结构及状态；`runs/run_events` 保存任务进度，`llm_calls` 保存模型、token、估算费用和价格版本。现有代码没有完整工具注册协议、退避执行器、每次尝试轨迹或独立失败用量保存路径。

| 阶段 | 本设计的实现门槛 |
|---|---|
| 1 | 严格故事/行动/规则 schema，确定性错误与状态不变约束，最小规则任务评测；不新增真实模型编排 |
| 2 | 文字与语义检查操作独立注册，统一执行、重试、截止时间、Trace 及失败用量；模拟故障与真实路径分别验收 |
| 3 | 图片操作、素材补缺、文字/图片原子预算预留、恢复轨迹 |
| 5 | OpenAI 适配器使用同一协议并独立验收 |
| 6 | 并行编剧/角色及审核修复共享任务截止时间、费用和 Trace；配对评测后才启用默认 |

工程化以明确接口、失败行为和证据为标准，不用无界 ReAct 循环替代流程。每个阶段只实现所需操作，普通纯函数不用包装成 Agent 工具，不引入 Redis、云 Trace 服务或额外编排框架。

## 2. 注册与统一执行边界

注册项 `ToolSpec` 必须有：`name`、`version`、严格 `input_schema/output_schema`、`handler`、`timeout_seconds`、`max_attempts`、可重试错误集合、`side_effect_policy`（pure/read_only/idempotent_external/non_idempotent_external）及该操作费用估算方式。重名同版本注册失败，未知名称/版本拒绝执行；运行时不能接受模型新定义的工具或 schema。

统一入口消费 `ToolSpec`、原始入参和服务端 `ExecutionContext`（trace/task/session ID、固定模型版本、总截止时间、预算、幂等标识），返回 `ToolResult` 判别联合：成功含验证后的输出和 usage，失败含 `error_code`、是否可重试、可公开消息及 attempt ID。每次执行都校验入参、权限与版本；密钥由后端设置注入 handler，不是模型可见入参，不能进入 Trace。

初始文字操作包括行动理解、故事设定生成、叙事生成及语义检查；阶段 3 增加图片生成，阶段 6 增加角色/审核操作。各操作入参出参用独立 schema，不能用一个无约束 `dict` 注册所有操作。共享供应商适配器可以复用 HTTP 连接与响应 envelope 校验，但只有适配器允许发供应商请求；编排代码禁止裸调 HTTP/API。

执行顺序固定：登记开始轨迹 → 严格输入校验与授权 → 预算检查 → 调用/等待 → envelope 与输出校验 → usage 记账 → 记录成功/失败 → 返回结构化结果。无效参数不发网络请求；业务拒绝与执行故障用不同代码表示；异常细节只进入脱敏内部轨迹，玩家收到稳定错误代码和恢复提示。

适配器提取 usage 不以候选正文 schema 通过为前提；无论后续解析、裁决或审核失败，都进入同一个 attempt 收尾路径保存已产生用量，不能在抛校验异常后直接跳过记账。

统一边界捕获 schema、权限、供应商、超时及 handler 的普通异常，转换为稳定错误码并记录原异常类别；未分类的普通异常为 `internal_error`，不返回成功空值、不自动重试。任务取消记录 cancelled 并继续传播取消信号，不能用裸 `except` 吞掉进程退出或取消。

## 3. 错误分类与有限重试

| 错误 | 自动重试 | 处理 |
|---|---|---|
| 未知工具/版本、参数错误、越权 | 否 | validation/authorization 错误，无外部调用 |
| 密钥缺失、401/403、模型未开放 | 否 | 配置错误，保留任务输入 |
| 明确限流 429、尚未发出请求的连接失败 | 满足安全、预算和截止时间时 | 有限退避，记录每次尝试 |
| 5xx、读超时、连接中断且远端结果未知 | 默认否；供应商证明可幂等重试时才允许 | 记录 outcome_unknown；避免重复收费或副作用 |
| envelope 缺字段、非法 JSON/schema、非法状态效果 | 否 | output_validation 错误，不通过网络重试掩盖 |
| 预算不足、任务取消、总截止时间耗尽 | 否 | blocked/cancelled/timeout，停止新调用 |
| Trace/费用持久化失败 | 否 | storage_failure，停止后续外部调用与节点提交 |

允许重试的调用总共最多三次（首次 + 两次重试）。退避为 `min(0.5 * 2^(attempt-1), 4)` 秒加 0–0.25 秒抖动；若供应商提供 `Retry-After`，至少等待其要求的时间；等待超过剩余任务时间则结束，不提前绕过限流。测试使用可控时钟和确定性抖动，不真实等待。

副作用判定优先于错误码：没有供应商幂等保障的外部生成调用即使 5xx/超时也不能盲目重新发出。不得自动重复节点提交；数据库事务重试须沿用任务幂等键并确认尚无已提交节点。每次供应商尝试都单独计入 Trace 和费用，禁止把重试包装成一次免费调用。

输出格式修复是单独、可计费且有明确原候选输入的操作，不是传输重试。故事设定检查和阶段 6 审核各最多触发一次修复，修复后仍不合法则失败；普通叙事格式错误默认失败且不提交节点，不新增无限自动纠错。旧引擎已有 `fallback=true` 兼容行为不改写旧内容，也不套用为新规则的隐式转场。

## 4. 超时与降级

普通行动任务总截止时间为 60 秒，包含所有外部调用、等待、校验与修复。文字单次调用最多 20 秒，实际可用时间不得超过剩余截止时间；HTTP 各阶段超时之外，执行器必须有覆盖整个 attempt 的墙钟超时。并行调用共享同一任务截止时间，不能每个阶段重置成 60 秒。

故事准备采用可查询/恢复任务，文字生成或检查单次最多 20 秒，图片单张调用最多 60 秒；创建任务外部调用与等待累计上限 300 秒，耗尽则标记中断并保留已批准故事/素材。显式恢复创建新的尝试区间并关联原任务，沿用预算及已完成结果，不重新生成已固定内容。开局一分钟左右仍是优化目标，不能用 300 秒保护上限声称目标已达成。

降级含义是可靠地结束本次操作：返回结构化错误、保留父节点/输入、暴露对应恢复入口、保持旧存档可回放。无效/重复行动使用规则反馈而非调用模型编造线索。新调查流水线的格式错误、工具失败或超时不自动移动、不发放证据、不产生半个节点，也不静默切换模型或模式。允许的旧过渡幕显式带 fallback 标记，不能计为正常模型任务成功。

取消后阻止后续阶段与提交；远端请求已发出时记录结果不确定和费用未确认，不能把“本地停止等待”写成“供应商已取消且不收费”。进程重启仍显式中断未完成任务，不自动重发供应商请求。

## 5. Trace 与费用持久化

Trace 记录可观测执行事件，包含任务开始、入参校验、授权、规则裁决、各次外部调用、退避、输出/状态校验、修复、提交和终态。一个任务一个 `trace_id`；每次操作有 `span_id/parent_span_id`，每个 attempt 单独编号，事件顺序有唯一序号。记录脱敏输入/输出（大内容可用本地 artifact 引用及 SHA-256）、故事/引擎/prompt/模型版本、耗时、错误、usage 及预算结算状态。

设计采用本地持久化执行记录，通过增量迁移新增 `execution_traces` 事件表：ID、trace/span/父 span、序号、task_type/task_id、session_id、可空 node_id/llm_call_id、event_type、attempt、timestamp、duration_ms、status/error_code 和脱敏 payload。任务类型为 creation/action/image；行动任务关联现有 run，创建与图片任务的归属在各自接口中校验。唯一约束 `(trace_id, seq)`，不能仅凭任意 task_id 跨会话读取。阶段 2 实现行动/创建所需字段，阶段 3 扩展图片职责。

并行 span 的序号分配使用对应持久化任务记录的数据库锁或原子计数，不用无锁 `max(seq)+1`；序号反映记录顺序，父子 span 和时间戳解释并行关系。任务尚无故事版本或提交节点时关联字段可空，但 task/session 归属必须明确；提交成功记录新节点关联，不修改此前事件。

`llm_calls` 仍为 token/费用账本，不存完整调用输入输出。阶段 2 增量扩展 attempt/trace 关联及调用状态、可空 usage 和估算未确认状态，并支持创建任务的关联；旧非空 run 关联与已记录费用保留，新增创建记录允许无行动 run，但必须有经授权的创建任务关联。具体迁移随对应任务模型一起实现和检查，不在文档整理时执行数据库变更。

开始事件必须在调用前持久化；调用返回或异常后，用独立事务保存 attempt 终态与可取得费用，再执行剧情提交。失败轨迹不能跟随剧情事务回滚；候选即使不合法也保留内部校验结果和实际 usage。供应商未返回 usage 的请求保存 outcome_unknown 和保守估算，不写零 token 伪装免费。事务提交失败记录独立终态，不将已有调用记账重复插入。

阶段 2 每次重试前重新检查文字预算；阶段 3 启用文字/图片原子预留后，每次 attempt 和修复均先预留再结算。未确认请求不能立即释放全部预留并让下一次调用绕过上限。Trace/账本暂时无法写入时，停止新调用、任务失败且无节点；已发出但无法持久化的 attempt 在恢复时标记审计不完整并保留预算不确定状态，不能宣称轨迹完整或费用已精确结算。

内部 Trace 不保存 API Key、Authorization、会话 token、连接凭据或隐藏模型思考；只记录可观测请求、结果与规则决定。内部候选稿和故事真相可用于本地审计，但不得进入玩家接口、SSE、角色公开资料或祖先提示。浏览器任务进度/批准事件与内部 Trace 是不同投影。日志文件及 artifact 使用 Git 忽略目录，发布包不携带用户轨迹。

## 6. 复盘与测试

轨迹复盘只读取保存的输入输出、各次尝试和结果，不重跑 handler、供应商或状态提交。剧情回放仍从不可变节点读取批准内容；内部 Trace 不参与分支生成上下文。重复幂等请求复用任务及其轨迹，显式新尝试记录关联，不能修改旧 attempt 结果。

执行器测试至少覆盖：未知工具/错误类型不调用 handler；401 不重试；可安全重试的 429 后成功；两次退避后耗尽；读超时结果未知不盲重发；Retry-After 超出总时限；非法 JSON/schema 不提交；一次修复仍失败；取消/超时后禁止状态修改；失败 usage 持久化；剧情回滚后 Trace 仍在；Trace 写失败停止调用；同幂等键并发；跨会话轨迹访问拒绝；日志/Trace 密钥脱敏。使用假供应商注入故障，真实验收单独记录。

阶段 3 加入图片部分成功后补缺、校验值复用、并行预留及未确认费用测试；阶段 6 加入并行 span、审核误报、修复上限和共享截止时间测试。成功率口径见[基础任务评测](../evaluation/task-success-baseline.md)，模拟故障通过不等于真实 AI 质量通过。
