## 1. 目标与当前基线

按 **游戏体验 → 求职作品交付 → 多 Agent 默认模式** 的顺序推进，取消原有按周划分的开发期限，保留阶段验收门槛。

最终产品是本地单人调查影游：玩家选择故事背景与年代，AI 生成并固定该局的角色、真相、证据链和配图；玩家扮演其中的主角，通过调查、交流、出示证据及自由行动推进故事。

首版默认每局 **3 位角色、5 个主要地点、3 个不同后果的结局**，目标约 15–25 次行动、20–40 分钟。按调查进度收束，不设置硬倒计时。《雾港最后一夜》保留为内置 Demo 和回归样本。

当前可沿用状态更新、不可变节点、分支存档、幂等任务和 SSE 通路。文档记录了 DeepSeek 一条真实路径验收；自定义故事、图像接入、完整调查玩法和多 Agent 均属于新增工作。

## 2. 核心实现设计

### 故事创建与规则

- 创建流程固定为：选择背景与年代 → 生成故事设定 → 校验 → 展示无剧透简介 → 玩家确认 → 生成配图 → 开始游玩。
- 故事设定包含角色知识与秘密、固定真相、调查对象、证据发现条件、主动事件及结局条件。采用服务端支持的声明式规则，禁止模型生成可执行代码。
- 校验实体引用、地点可达性、线索依赖及结局可达性；增加语义检查评估证据是否支持真相。检查不通过时最多修复一次，仍失败则停止创建。
- 每局设定批准后固定。玩家和运行中的 Agent 均不能改写真相；浏览器只接收玩家当前可知的信息。

### 调查与生成

- 将行动回合与地点切换分开，允许同一地点多轮调查和交流。
- 普通流水线采用“AI 理解行动 → 服务端裁决 → AI 演绎回应”。调查、追问、出示证据、移动和最终抉择共享确定性规则。
- 重复、无效或不成立的行动给予明确回应，不自动推进到下一地点或发放线索。
- 角色主动行为由证据、信任和调查进度触发。重要披露、承诺与事件写入结构化状态，配合最近三个祖先回合构成上下文。
- 最终多 Agent 链路为：导演理解行动 → 服务端裁决 → 编剧与出场角色并行生成 → 审核 → 服务端校验与提交。审核最多触发一次修复，不能覆盖服务端事实。

### 图片与费用

- 使用指定的 `cogview-4`，首版采用 `standard` 画质；背景默认 `1344x768`，人物图默认 `768x1344`。这些参数属于官方接口支持范围。[智谱图像接口](https://docs.bigmodel.cn/api-reference/%E6%A8%A1%E5%9E%8B-api/%E5%9B%BE%E5%83%8F%E7%94%9F%E6%88%90)
- 每局生成五张背景和三张人物图；封面及结局复用已有素材。统一使用角色外貌、年代服饰和美术风格描述，固定图片后再开始游玩。
- 图片保存到本地，记录模型、提示版本和文件校验值；回放直接读取保存的素材。失败后仅重试未完成部分，不重新生成整套故事。
- 文字与图片共用 **80 元提醒、100 元停止新调用** 的预算。调用前检查并预留费用，完成后按实际 token 或图片张数记账，包括修复和失败任务中已产生的用量。
- 实际接入前核实 CogView-4 单价并版本化记录；当前未读取到官方定价，不填入未经确认的价格。所有供应商密钥只保存在后端进程内存。

### 前端与存档

- 重设计故事库、创建故事、准备进度、游玩、结局与回放流程。沿用 Next.js 静态导出，以固定页面加查询参数定位故事，避免依赖运行时动态服务端页面。
- 游玩界面以背景、人物与对白为中心；证据、人物资料和分支记录按需展开。
- 支持点击人物交流、调查对象面板、选择证据后出示、地点切换和自由输入。
- 加入逐句对白、点击显示完整句子、历史对白、文字速度、键盘操作及减少动画选项。生成失败保留输入，并提供具体恢复入口。
- 故事库保存各局会话凭据、当前位置和未完成任务，支持关闭浏览器及重启后继续；API Key 不进入浏览器存储。
- 新状态与故事设定使用版本标识。旧节点不重写，旧故事继续使用兼容路径回放。

### 接口与数据边界

- 新增故事创建任务接口，支持创建、查询进度、SSE 补发及显式恢复；创建和行动任务均支持幂等提交。
- 增加按会话获取世界信息及素材的接口，校验故事归属，并过滤隐藏真相与未发现线索。
- 扩展会话元数据，固定故事版本、引擎版本、生成模式及文字、图片模型。
- 将前端硬编码角色和场景改为故事提供的 ID；现有节点、分支、行动和任务接口保持兼容。
- 节点与批准后的渲染内容仍不可变；所有状态变更通过现有统一更新路径提交，候选正文不提前发送到浏览器。

### 工程可靠性与复盘

- 应用工具和外部调用通过独立注册项及统一执行入口；严格校验入参/出参，统一异常分类，不允许编排代码直接调用供应商 HTTP。
- 安全瞬态故障采用有限指数退避，永久错误或格式错误不盲目重试；任务截止时间、幂等及预算约束覆盖每次尝试和修复。超时不伪造成功或提交半个节点。
- 成功与失败都记录脱敏输入输出、校验、各次尝试、耗时、用量和终态，关联任务、节点及 `llm_calls`；调用费用表不能代替完整 Trace。轨迹与已产生费用不随剧情回滚丢失。
- 阶段 1 的规则案例集必须有可执行成功率入口；后续扩展工具失败、格式错误、超时及重试耗尽案例，规则/模拟/真实结果分别报告。入口统一用 `evals/`，不另建 `benchmark/`。

## 3. 开发顺序与目录职责

每阶段采用“更新规范 → 实现 → 测试 → 本地验收 → 开发日志 → 相关提交”的闭环。

| 阶段 | 交付内容 | 进入下一阶段的条件 |
|---|---|---|
| 0．更新基线 | 修订 AGENTS.md 和三份主文档，记录新需求、兼容策略及验收标准 | 文档范围一致，保留已有验收历史 |
| 1．故事数据与规则 | 建立版本化故事协议、校验器、调查状态与最小规则任务评测；由助手起草完整雾港样本，用户审定 | 样本线索及三个结局可达，旧存档回放通过，固定案例成功率可复现 |
| 2．自定义故事与普通流水线 | 接入背景、年代生成；实现行动理解、规则裁决、角色事件、叙事生成及注册调用、重试、超时、Trace | 不同背景均能创建并走完，分支隔离、格式错误、调用故障与超时测试通过 |
| 3．图片、前端与存档 | 接入 CogView-4，重设计完整页面流程，完成调查交互和故事库 | 创建、游玩、关闭后恢复、旧节点回放均可实际操作 |
| 4．可玩版本交付 | Windows 便携运行包、故障排查和完整试玩验收 | 干净 Windows 环境无需开发工具即可启动，Demo 可离线游玩 |
| 5．求职作品与 OpenAI 文字支持 | 架构图、演示录屏、基线评测报告；独立接入并验收 OpenAI 文字模型 | 展示结论有证据；OpenAI 完整路径实测后才开放 |
| 6．多 Agent 默认版本 | 实现职责分工、并行生成、审核修复及配对评测，更新便携包 | 达到可用性和时延门槛后，新故事默认使用多 Agent |

目录按职责补齐，围绕本次需求调整现有模块：

```text
docs/
  三份主文档
  development-log/       里程碑记录、实际验证、问题和提交
  design/                故事协议、接口与前端设计
  evaluation/            评分标准、评测报告
backend/
  app/                   故事创建、规则、生成、供应商和素材模块
  migrations/            版本化增量迁移
  tests/                 单元、集成测试与固定故事样本
frontend/
  app/                   固定页面入口
  components/            舞台、调查、记录和创建流程组件
  lib/、store/           API、类型与按故事管理的客户端状态
  public/                内置 Demo 素材
evals/                    固定案例与可复现评测入口
scripts/                  开发启动、验证与便携包构建
```

生成故事、用户图片、数据库、密钥和本地日志放入 Git 忽略的运行数据目录。四份现有未跟踪草稿保持独立，未经明确纳入与验证不进入提交。

便携包包含 Python 运行时、静态前端和 PostgreSQL；启动器检查端口、初始化独立数据目录、执行迁移并启动本地服务。停止时只管理自己启动的进程，发布包不携带用户数据或密钥。

## 4. 验收、评测与默认边界

- **规则与兼容**：覆盖无效行动、非法状态、证据依赖、重复调查、结局可达性、旧存档，以及修改模型或提示后仍原样回放。
- **隔离与恢复**：覆盖跨故事访问、兄弟分支污染、同幂等键真实并发提交、断线补发、进程重启和未完成图片任务恢复。
- **模型与费用**：覆盖无密钥、失效密钥、网络故障、非法输出、审核误报、修复失败及并行调用的预算保护；失败不得产生半个剧情节点。
- **工程与基础评测**：阶段 1 起有固定任务案例和成功数/总数/失败明细；后续注册调用覆盖未知工具、参数错误、瞬态/永久错误、超时、重试耗尽、Trace/账本故障及恢复。模拟通过不能替代真实模型验收。
- **真实游玩**：至少验收古代、近现代和未来三种背景；检查调查公平性、角色可信度、行动反馈、图片年代匹配，以及开局和完整游玩耗时。
- **前端与便携包**：运行相关测试、TypeScript 检查和生产构建；验证键盘、窄屏、长对白、错误恢复，以及干净 Windows 环境的启动和退出。
- **对照评测**：冻结故事、父状态、行动、模型和上下文，用至少 30 组配对案例比较普通流水线与多 Agent；分别记录首次输出合法率、回退率、事实冲突、时延、用量和费用。用户按统一评分表参与人工评价，报告标明一位评审。
- **性能目标**：开局以一分钟左右为优化目标；普通行动通常 10–20 秒、p95 不超过 60 秒。按实际结果报告，未达标阶段继续优化。
- **最终定位**：多 Agent 必须成为最终默认方案，但不预设它一定优于基线。未通过验收时不宣称最终版本完成；收益和代价均如实写入报告。

默认交付 Windows 本地单人版本，文字首版使用 DeepSeek；保持无密钥 Demo。暂不加入云部署、多用户、开放世界扩展、pgvector、Redis、配音和存档导入导出。
