对应文档：[需求](01-requirements.md) · [开发与验收](03-development-plan.md) · [已确认扩展计划](design/implementation-plan.md)

## 1. 架构与当前实现

```text
Next.js 静态前端：故事库 / 创建 / 准备 / 舞台 / 结局 / 回放
  └─ 带会话认证的本地 HTTP + fetch SSE
          ↓
FastAPI 单进程（仅监听 127.0.0.1）
  ├─ 故事创建与版本化设定校验
  ├─ 行动理解 → 确定性调查裁决 → 叙事生成
  ├─ 严格结构校验 → 统一状态更新 → 单事务提交
  ├─ 本地素材与可恢复图片任务
  ├─ 进程内供应商密钥 / 文字与图片共享预算
  └─ PostgreSQL：故事版本、会话、不可变节点、事件、任务、用量
          ↓
DeepSeek 文字 / CogView-4 图片
OpenAI 文字（阶段 5） / 多 Agent 编排（阶段 6）
```

上图是目标架构。当前实现是固定 `canon.json`、Demo / DeepSeek 单次生成、PostgreSQL、不可变节点、幂等任务及批准后 SSE；前端采用静态导出和单故事 `sessionStorage`。自定义设定、同地点调查、图片、跨浏览器重启的故事库、便携包、OpenAI 和多 Agent 尚待验收。保留浏览器直连本地 API，不接云服务、Redis 或 pgvector，只允许本地前端 origin。

## 2. 版本化故事与调查规则（阶段 1）

故事协议包括背景年代、无剧透简介、角色知识与秘密、地点及可达关系、调查对象、固定真相、证据发现条件、主动事件和结局条件。采用声明式条件及效果的服务端白名单，不执行模型返回的代码。具体字段与受支持操作在阶段 1 的故事协议设计中固定，不能把本阶段说明当作已存在的 schema。

创建校验依次检查结构、实体引用、地点可达性、证据依赖及结局可达性，并语义检查证据是否支持真相。整次设定检查最多允许一次修复；修复后重新检查全部约束，仍失败则停止。用户只看到过滤后的简介；确认后保存不可变故事版本，运行时不能修订真相或证据规则。

新调查状态记录当前地点、行动回合、已知证据、角色信任及披露、承诺、主动事件和结局状态。同地点多轮行动合法，移动是独立裁决结果；重复调查或条件不满足不能自动转场或发放线索。终局由调查进度及结局条件决定，不使用硬倒计时。结构化状态与最近三个祖先回合共同构成生成上下文。

所有状态变更仍通过 `apply_state_changes()` 所在的统一更新路径。阶段 1 为新引擎增加版本分派及规则校验，同时保留旧引擎逻辑；禁止生成器、审核或图片任务直接修改世界状态。《雾港最后一夜》的新调查样本由助手起草、用户审定，须证明线索与三个结局可达。

## 3. 普通流水线与多 Agent

阶段 2 普通流水线：读取固定故事、父状态及祖先上下文 → AI 理解行动 → 严格校验行动提案 → 服务端裁决合法目标、条件、状态效果及可披露信息 → AI 演绎回应 → 结构及确定性状态校验 → 单事务提交。调查、追问、出示证据、移动和最终抉择使用相同裁决入口；AI 无权自行发放证据、移动或改写真相。

角色主动事件依据证据、信任和调查进度触发，重要结果记录结构化状态及已提交事件。失败不提交半个节点，无效行动给出规则决定的明确回应。新协议的输出格式与失败恢复在阶段 2 设计中确定，不能直接照搬旧协议“每次行动推进场景”的行为。

阶段 6 最终链路：导演理解行动 → 服务端裁决 → 编剧与出场角色并行生成 → 审核 → 服务端校验与提交。审核只返回检查与修复建议，最多触发一次修复；全部调用共享会话固定的模型、预算、提交及存档协议。事实优先级为 **固定故事与规则 → 父状态 → 祖先已提交事件 → 审核意见 → 提示材料**。

普通流水线保留作为评测基线。多 Agent 通过可用性、故障处理及时延门槛后仅成为新故事默认；旧会话固定的模式、模型和版本不改变。自然语言与角色可信度仍需语义检查和人工评价，不能只凭 schema 合法宣称叙事一致性已解决。

## 4. 数据与旧存档兼容

| 数据职责 | 当前实现 | 后续扩展 |
|---|---|---|
| 故事设定 | 固定 `canon.json` | 批准后固定的每局故事版本，公开投影与隐藏真相分开 |
| `sessions` | 令牌哈希、固定供应商及文字模型 | 固定故事版本、引擎版本、生成模式、文字与图片模型 |
| `nodes` | 父节点、深度、快照、批准渲染及设定/prompt/模型版本 | 新调查状态和故事 ID；旧内容不重写 |
| `turn_events` | 玩家行动、批准剧情、状态变更 | 已批准披露、承诺及规则触发事件 |
| `runs` / `run_events` | 行动任务、幂等键、可补发序号事件 | 创建与图片任务的持久化进度、幂等提交、显式恢复 |
| `llm_calls` | 文字 token、估算费用、价格版本 | 共享文字/图片费用账本、预留、失败及修复用量 |
| 本地素材 | 内置 Demo 素材 | 按故事归属保存文件、模型、提示版本及校验值 |

新增数据及版本字段使用 Alembic 增量迁移，不重建用户数据库、不重写已有节点或批准渲染。缺少新版本字段的旧会话归入旧引擎兼容路径；旧 `schema_version`、`scene_id`、`turn`、`flags`、`relations`、`ending_id` 的意义不变。新故事使用协议提供的角色和地点 ID，解除 Demo ID 和场景字段长度对新故事的限制；具体迁移在对应阶段验证。

回放读取保存的批准内容、状态与素材，不调用生成器，不因换模型、提示或价格版本重新生成。分支从选中父节点向祖先遍历，按时间正序构造最近三个回合，禁止包含兄弟分支。旧上下文 `single-2` 保留原裁剪：历史行动最多 120 字、叙述 240 字、每句旧对白 100 字；当前行动不裁剪。

## 5. API、授权、SSE 与恢复

现有 `POST /sessions`、`GET /session`、`POST /turns`、`GET /nodes/{id}`、`GET /nodes/{id}/events`、`GET /tree`、`GET /runs/{id}` 和 `GET /runs/{id}/events?after=N` 保持旧调用兼容。会话创建缺省 `demo`，返回一次会话令牌；供应商及模型创建后固定。`GET /local-settings` 只返回模型列表、密钥配置布尔值及预算状态；`PUT/DELETE /local-settings/keys/{provider}` 当前仅开放 DeepSeek，OpenAI 继续返回待验证错误。

阶段 2–3 增加故事创建任务的创建、进度查询、SSE 补发、玩家确认及显式恢复接口，以及按会话获取世界信息与素材的接口。路径及请求/响应协议在该阶段接口设计中固定，不把它们写成当前可调用接口。创建和行动均支持幂等提交：同键同输入复用任务，同键不同输入拒绝；真实并发不能产生第二个任务或节点。

当前未认证的 `GET /world` 仅保留旧 Demo 公开数据。新世界、素材、节点、事件、任务及分支接口须校验会话和故事归属；对玩家返回的状态、对白、事件、进度及素材元数据做公开投影，过滤隐藏真相、角色秘密与未发现线索。不得通过旧接口或素材提示词绕过过滤；响应过滤不改变数据库中的原始快照或批准内容。

阶段进度可实时发送；`scene_chunk`、`options`、`done` 仅在校验及事务提交后发送，未批准正文不得流向浏览器。使用带认证头的 fetch SSE，以持久化序号 `after=N` 补发；断线只影响读取，后端任务继续。跨故事任务与素材访问拒绝。

当前重启将未提交任务标为 `interrupted`，不自动再次调用供应商。新创建/图片任务保留已批准设定及已完成素材，以显式恢复补未完成部分；行动失败可从原父节点重新提交，新幂等键表示新尝试或新分支。供应商请求发出但结果丢失时，无法保证第三方绝对只计费一次，须记录实际可取得的用量与恢复行为。

## 6. 图片、密钥与共享预算（阶段 3）

采用 `cogview-4`，计划参数为 `standard`，背景 `1344x768`、人物 `768x1344`；接入时核实[官方图像接口](https://docs.bigmodel.cn/api-reference/%E6%A8%A1%E5%9E%8B-api/%E5%9B%BE%E5%83%8F%E7%94%9F%E6%88%90)与官方单价。当前图片价格未确认，不填未经验证的数字。每局五张背景、三张人物，统一外貌、服饰与美术风格，封面及结局复用素材。

图片保存到 Git 忽略的本地运行目录，记录模型、提示版本、文件校验值及故事归属。整套图片固定后进入游玩；恢复仅生成未完成图片，回放直接读取本地文件。发布包包含内置 Demo 素材，不包含用户图片、数据库、密钥或本地日志。

所有供应商密钥经本地设置接口进入后端内存，不进入数据库、浏览器存储、日志或响应；重启须重填。当前文字费用仅汇总已记录的 `llm_calls`，尚无共享图片账本或并行预留保护。阶段 3 建立共享账本：调用前检查“已支出 + 已预留 + 本次预估”，达到 80 元提醒、达到 100 元停止新调用；原子预留避免并发绕过上限，完成后按实际 token/图片张数结算并释放未使用预留。

修复及已产生用量的失败调用同样记账；缺少实际 usage 的请求保留估算与未确认状态，不按零费用处理。供应商价格、汇率及提示版本需版本化。预算是本地估算保护，不保证最终账单绝不超额，不能通过拆分文字/图片任务规避。

## 7. 前端、故事库与本地交付

沿用 Next.js `output: "export"`，使用固定页面和查询参数定位故事，避免运行时动态服务端页面。故事库、创建、准备进度、舞台、结局与回放共用故事提供的角色/地点 ID，不以 `c1`/`s1` 等 Demo ID 作为新故事的固定列表。

故事库在浏览器持久化存储中按故事保存会话凭据、当前节点、未完成任务、幂等键及 SSE 序号，不存供应商 API Key。保留旧 `sessionStorage` 存档恢复入口，转换客户端索引不得重写服务端旧节点。关闭浏览器及重启后恢复属于阶段 3 新验收，不能由当前刷新恢复推断。失败保留输入并提供具体恢复入口。

舞台以背景、人物与对白为中心，证据/人物资料/分支记录按需展开；提供人物交流、调查对象、出示证据、移动及自由行动。逐句对白、完整句显示、历史对白、速度、键盘及减少动画设置均需前端验收。

阶段 4 便携包包含 Python 运行时、静态前端及 PostgreSQL。启动器检查端口，初始化独立数据目录、执行迁移并启动本地服务；停止只管理自己启动的进程。开发仍使用 `scripts/start-local.ps1`，数据库配置在 Git 忽略的 `backend/.env`；迁移优先级为 `MIGRATION_DATABASE_URL` → `DATABASE_URL` → `.env`。迁移及破坏性测试仅使用独立测试库。

## 8. 验证与评测边界

阶段门槛见[开发与验收](03-development-plan.md)。覆盖规则/证据/结局可达性、不可变回放、跨故事授权、兄弟分支隔离、真实并发幂等、SSE、重启、图片补缺、非法输出及并行预算。古代、近现代、未来三种背景均须实际创建并完整游玩；便携包在干净 Windows 环境验证。

开局以一分钟左右为优化目标，普通行动通常 10–20 秒、p95 不超过 60 秒，按实际结果记录。阶段 5 建立普通流水线基线；阶段 6 冻结故事、父状态、行动、模型及上下文，以至少 30 组配对案例记录合法率、回退率、事实冲突、时延、用量及费用，一位用户评审按统一量表评分。未达到门槛时继续优化，不宣称最终默认、多模型支持或简历收益已完成。

## 9. 旧引擎兼容协议

旧 `canon.json` 固定场景、合法转移、角色卡和允许 flag；关系值 -3..3，flag 仅允许白名单中的 0/1。旧生成器先确定下一场景及选项，再生成 `narration`、1–2 位出场角色的 `dialogue` 和最多 4 个 `state_changes`；模型无权改变路由，严格 Pydantic 校验后走统一状态更新与单事务提交。

旧候选格式或状态提案不合法时，使用目标场景预写的 `fallback=true` 过渡幕，状态变更为空；密钥、网络或额度错误令任务失败且不创建节点。旧协议不自动识别叙述、对白与禁忌的语义冲突，不能宣称完整调查引擎。旧输入目标上限 4,000 token、输出上限 900 token，字符守卫不等于精确 token 统计。旧会话与节点按保存的版本解释，新引擎能力不能反向套用到旧存档。
