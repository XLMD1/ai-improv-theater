3. 基线按明确分母报告任务成功、首次输出结构合法、回退、修复、事实冲突人工结论、时延、usage、价格版本及费用估算。规则、模拟、真实、人工四种证据分开。
4. 交付实际浏览器录屏和复现说明，录屏可以采用无密钥 Demo，并明确其只证明界面与存档流程、不证明模型质量。生成故事、用户图片、原始报告、数据库及浏览器凭据使用忽略的 runtime 目录；仓库保存安全的聚合指标，以及只含内置 Demo、无凭据和私有剧情的公开录屏及封面。
5. 更新 README、架构文档、阶段状态和开发日志；保留历史失败和现有四份草稿。

## 评测边界

- 沿用阶段二固定 12 项（三创建、九路径）；不能按成功与否挑选来源，源报告哈希与清单哈希必须匹配。原始故事和路径在调用前已经冻结，采集时再次核对。
- 来源限定真实 `real_model_with_approved_feedback` 报告；从报告声明的会话/任务/父链读取数据，数据库连接必须是 PostgreSQL `_test`，整个采集事务只读。仅 replay 数值计算时不连接数据库、不调用 provider。
- 首次结构合法率检查每个任务/操作第一次 attempt 的原始输出，用原操作版本的严格 schema 验证；HTTP/缺失输出计不成功。它不等于语义正确率。
- 回退率按保存的非根回合 `fallback` 字段计算；R1 的服务器反馈不算模型叙事，也不是 fallback。
- 保存回合时延按 task_started 至 node_committed 计算，按钮与自由文字分开；缺失数据显式计数，不写零。失败 run 的轨迹与费用保留，未保存节点不进入回退或保存回合时延样本。不以整条路径时间代替单回合 p95。
- 人工评价只采用与同一 run 匹配的已保存人工验收，记录日期、人数、故事范围与发现的问题；不能从规则通过自动推导无事实冲突。
- 用量来自实际 attempt 关联的 llm_calls；不拿时间窗口内的其他任务计费。失败路径保留所有已提交 run ID；旧报告缺失败 ID 时明确覆盖不全，不报告完整费用。缺 attempt 或应计费账单拒绝，未知费用不按零收费；不宣称供应商账单已核验。
- 成功路径必须匹配固定清单的结局索引、输入模式和冻结行动序列；报告、冻结文件、创建 checkpoint 及保存呈现协议互相核对版本。离线包保存完整性 hash、原账单快照和人工记录 hash，重算核对计数、重试顺序并重新汇总费用；hash 用于检测改动，不是来源真实性签名。
- 使用历史记录时同时报告原始 commit/prompt/模型版本和本次采集版本，明确不证明当前提示版本的新样本质量。

## 验收

- 新入口有负例：失败/跳过保留分母、错误来源、哈希不符、跨会话路径、缺 trace、无法确认 usage、人工 run 不符、只读采集与零外部调用。
- 新入口可在干净源码上运行已有规则/模拟套件；真实评测须独立测试库和用户在终端隐蔽输入的内存密钥。
- 录屏来自本轮实际运行的页面，附录制方法与本地证据 JSON；静态导出另行构建验证。演示不包含凭据或隐藏剧情。
- 报告及开发日志只写实际执行结果；缺少的证据保留未完成状态。无需重新验收已取消 OpenAI/多 Agent，也不重新验收手机和自动生图质量。
