# AI 即兴剧场：需求文档

版本：v0.1（开发基线）
状态：阶段 1 已完成本地验收；真实模型、评测和上线仍待后续阶段

## 1. 产品目标

做一个可在线演示的单人互动影游。玩家选择选项或输入行动后，系统生成下一幕；玩家可以回退、探索另一分支、查看人物关系，并且旧剧情能够原样回放。

项目的简历价值建立在可验证的状态一致性、分支隔离、生成流程评测上。多 Agent 的价值必须由实验数据证明，不能只靠角色数量或提示词数量宣称。

## 2. 首版范围

- 一个固定世界：《雾港最后一夜》；3 个角色、5 个场景、3 个结局，每幕最多 2 位角色出场。
- 视觉小说式单页 Web 界面：预制场景和角色画面、文字对白、选项、自由输入、生成进度。
- 每次已批准的剧情成为不可变节点，节点保存完整世界状态和渲染内容；从任意非结局节点可生成新分支。
- 关系图显示三组角色关系值；分支列表可以回看节点。
- 同一选择可通过单次模型方案或多 Agent 方案生成，用固定测试集比较质量、延迟和成本。
- 公开 Demo 支持匿名会话，但每会话每日最多 20 幕，并设置全站模型费用上限。

首版不包含账号、多用户实时同步、直播、实时视频生成、开放世界编辑器、动态图片生成、Redis 队列和每日摘要。

## 3. 玩家流程与验收

1. 首次打开页面，系统创建匿名会话并展示第一幕；刷新后仍能回到当前节点。
2. 玩家点击选项或提交不超过 500 字的自由行动，立即看到阶段进度；审核完成前不展示候选正文。
3. 生成成功后，展示已批准的正文、对白与下一轮选项，自动保存节点和关系状态。
4. 玩家在分支列表中选择任意旧节点，看到原文和当时的状态，不重新调用模型。
5. 玩家从旧节点另作选择时，新节点与其他分支的状态及记忆相互隔离。
6. 断线后页面可继续读取同一生成任务；重复提交相同幂等键不会创建第二个节点。
7. 生成失败时不留下半个节点；任务失败或被标记中断后，玩家可以重新发起选择。

## 4. 内容与质量边界

- 固定设定与已提交状态是事实来源；模型只提出剧情与状态变更建议。
- 状态变更必须通过服务端规则校验；审核 Agent 不能直接写数据库。
- 角色卡包含目标、禁忌及 `risk`、`loyalty`、`secrecy` 三个行为值（0–2）。
- 每幕模型总耗时目标不超过 60 秒。单次模型和多 Agent 的效果均按同一套 40 个输入、每个 3 次进行盲评；阈值与评分方法见技术设计。
- Demo 模式仅用于离线开发与存档链路演示。它的确定性文本与伪向量不得计入 AI 质量评测或简历数据。

## 5. 交付定义

第一阶段先交付三文档并审阅需求边界。之后每阶段完成对应代码、测试和本地验收，再提交一次符合 `English: 中文` 格式的 commit。在线 Demo、真实模型评测和简历指标分别作为后续独立验收项；文档创建不代表项目完成。
