# AI 即兴剧场：需求文档

版本：v0.3（本地 DeepSeek 优先开发基线）
状态：阶段 1 已完成本地验收；DeepSeek 单次路径已实测，OpenAI 密钥选择待开发验证

## 1. 产品目标

做一个本地单人使用的互动影游。玩家选择选项或输入行动后，系统生成下一幕；玩家可以回退、探索另一分支、查看人物关系，并且旧剧情能够原样回放。GitHub 仓库、可复现的本地运行说明和演示录屏是最终展示形态，不承诺在线 Demo。

项目的简历价值建立在可验证的状态一致性、分支隔离、生成流程评测上。多 Agent 的价值必须由实验数据证明，不能只靠角色数量或提示词数量宣称。

## 2. 首版范围

- 一个固定世界：《雾港最后一夜》；3 个角色、5 个场景、3 个结局，每幕最多 2 位角色出场。
- 视觉小说式单页 Web 界面：预制场景和角色画面、文字对白、选项、自由输入、生成进度。
- 每次已批准的剧情成为不可变节点，节点保存完整世界状态和渲染内容；从任意非结局节点可生成新分支。
- 关系图显示三组角色关系值；分支列表可以回看节点。
- 保留无密钥确定性 Demo；真实生成先使用 DeepSeek `deepseek-flash` 的单次模型方案。OpenAI 卡片只显示“待开发验证”，禁用其密钥与新故事入口；每个已创建会话固定供应商和模型。多 Agent 仅在单次方案稳定后作为实验模式加入。
- 设置弹窗可配置、查看和清除 DeepSeek API Key，并显示固定模型；OpenAI 密钥选择功能暂不开放。密钥仅存在本地后端进程内存中，后端重启后须重填；不做账号或密钥持久化。
- 本地运行期间记录实际 token 用量与估算费用，80 元提示、100 元阻止新模型调用；预算保护不能保证第三方账单绝不超额。

首版不包含账号、多用户实时同步、直播、实时视频生成、开放世界编辑器、动态图片生成、Redis 队列、pgvector、每日摘要、云部署、任意模型 ID 或额外供应商。

## 3. 玩家流程与验收

1. 首次打开页面，系统创建无密钥 Demo 会话并展示第一幕；刷新后仍能回到当前节点。用户可在设置弹窗配置密钥，为下一段新故事选择供应商和模型；修改设置不改变当前故事。
2. 玩家点击选项或提交不超过 500 字的自由行动，立即看到阶段进度；结构与状态校验完成前不展示候选正文。
3. 生成成功后，展示已批准的正文、对白与下一轮选项，自动保存节点和关系状态。
4. 玩家在分支列表中选择任意旧节点，看到原文和当时的状态，不重新调用模型。
5. 玩家从旧节点另作选择时，新节点与其他分支的状态及祖先上下文相互隔离。
6. 断线后页面可继续读取同一生成任务；重复提交相同幂等键不会创建第二个节点。
7. 生成失败时不留下半个节点；任务失败或被标记中断后，玩家可以重新发起选择。未配置或失效密钥、额度和网络错误不得伪装成成功剧情；旧节点仍可回放。

## 4. 内容与质量边界

- 固定设定与已提交状态是事实来源；模型只提出剧情与状态变更建议。
- 状态变更必须通过服务端规则校验；审核 Agent 不能直接写数据库。
- 角色卡包含目标、禁忌及 `risk`、`loyalty`、`secrecy` 三个行为值（0–2）。
- 每幕模型总耗时目标不超过 60 秒。先验证 DeepSeek 完整一局；OpenAI 另行开发验证，未实测前不开放。质量、时延与费用只报告实际测试得到的数据。无法保证两位独立评审，不预设 40×3 双人盲评结论。
- Demo 模式仅用于本地开发与存档链路演示。它的确定性文本不得计入 AI 质量评测或简历数据。

## 5. 交付定义

三文档是开发基线；阶段 1 的完成记录保留。后续每阶段先更新文档，再完成代码、测试和本地验收，最后提交符合 `English: 中文` 格式的 commit。DeepSeek 验收不能写成“双模型可用”；OpenAI 必须另行实测完整一局才能开放并纳入简历。若多 Agent 未验收，简历名称改用“可回放互动叙事引擎”。
