# AI 即兴剧场：需求文档

版本：v0.4（自定义调查故事与沉浸式体验基线，2026-10-09）
对应文档：[技术设计](02-technical-design.md) · [开发与验收](03-development-plan.md) · [已确认扩展计划](design/implementation-plan.md)
状态：新增范围尚待逐阶段实现；已有验收记录见开发计划的历史部分。

## 1. 产品目标与已有基线

产品是 Windows 本地单人调查影游。玩家选择故事背景与年代，AI 生成并固定该局的角色、真相、证据链和配图；玩家扮演主角，通过调查、交流、出示证据与自由行动推进故事，并可回退探索分支、原样回放旧剧情。

交付顺序固定为 **游戏体验 → 求职作品交付 → 多 Agent 默认模式**。GitHub 仓库、可复现的本地运行说明、Windows 便携包、架构图、演示录屏与评测报告构成展示材料。取消按周划分的开发期限，保留阶段验收门槛。

现有基线已有固定世界《雾港最后一夜》、无密钥确定性 Demo、状态更新、不可变节点、分支存档、任务幂等、SSE 及最近三个祖先回合上下文。2026-10-08 的记录只证明 DeepSeek 一条四回合真实路径可用，不代表三个 AI 结局均实测或叙事质量、时延已有统计结论。新增阶段与旧阶段编号分开记录。

## 2. 本轮范围

### 2.1 故事创建与调查玩法

- 首版每局默认 3 位角色、5 个主要地点、3 个不同后果的结局，目标约 15–25 次行动、20–40 分钟；按调查进度收束，不设硬倒计时。
- 创建顺序：选择背景与年代 → 生成故事设定 → 校验 → 展示无剧透简介 → 玩家确认 → 生成配图 → 开始游玩。
- 设定包含角色知识与秘密、固定真相、调查对象、证据发现条件、主动事件及结局条件。采用服务端支持的声明式规则，禁止模型生成可执行代码。
- 校验实体引用、地点可达性、线索依赖与三个结局可达性，并语义检查证据是否支持真相；整次设定检查最多修复一次，仍失败则停止创建并说明原因。
- 每局设定批准后固定；玩家及运行中的 Agent 都不能改写真相。浏览器只接收玩家当前可知的信息。
- 行动回合与地点切换分开，同一地点允许多轮调查和交流。调查、追问、出示证据、移动与最终抉择由确定性规则裁决。
- 重复、无效或条件不成立的行动给出明确回应，不自动移动、不发放线索。角色主动行为由证据、信任与调查进度触发；重要披露、承诺及事件写入结构化状态。
- 分支仅使用选中父节点及其祖先。《雾港最后一夜》保留为内置 Demo 和回归样本，新调查样本由助手起草、用户审定。

### 2.2 生成模式与供应商

- 首版文字采用 DeepSeek 受控模型，保留无密钥确定性 Demo。普通流水线为“AI 理解行动 → 服务端裁决 → AI 演绎回应”。
- 每局固定故事版本、引擎版本、生成模式及文字、图片模型；修改设置只影响后续新故事，不改变已有存档。
- OpenAI 文字支持在阶段 5 独立接入并实测完整路径后才开放。现有 OpenAI 卡片和密钥、新故事入口继续显示“待开发验证”。
- 最终多 Agent 流程为“导演理解行动 → 服务端裁决 → 编剧与出场角色并行生成 → 审核 → 服务端校验与提交”，审核最多触发一次修复，不能覆盖服务端事实或直接写数据库。
- 多 Agent 是阶段 6 的最终默认目标；通过可用性和时延门槛后，仅新故事默认启用。未通过时保持已验收的普通流水线，不能宣称最终版本完成。

### 2.3 图片与预算

- 使用 `cogview-4`，首版计划采用 `standard`，五张背景默认 `1344x768`、三张人物图默认 `768x1344`。封面及结局复用素材，不额外生成。参数依据已确认扩展计划；实际接入时核实接口支持范围。
- 统一角色外貌、年代服饰与美术风格描述，图片保存到本地并固定后再开始游玩。记录模型、提示版本及文件校验值；回放读取保存素材。
- 失败后保留已批准故事和已完成图片，显式恢复只重试未完成部分，不重新生成整套故事。
- 文字与图片共用 **80 元提醒、100 元停止新调用** 的预算。调用前检查并预留费用，完成后按实际 token 或图片张数记账，包括修复和失败任务中已产生的用量。
- 接入前核实并版本化 CogView-4 官方单价；当前单价未确认，不填估价或据此宣称图片功能可用。预算是估算保护，不能保证第三方账单绝不超额。
- 所有供应商密钥只保存在后端进程内存；设置可配置、查看配置状态及清除密钥，重启须重填。密钥不写数据库、浏览器存储、日志或响应明文。

### 2.4 沉浸式界面与存档

- 重设计故事库、创建故事、准备进度、游玩、结局与回放流程；沿用 Next.js 静态导出，以固定页面和查询参数定位故事。
- 舞台以背景、人物与对白为中心；证据、人物资料及分支记录按需展开。支持点击人物交流、调查对象面板、选择证据后出示、地点切换及不超过 500 字的自由输入。
- 支持逐句对白、点击显示完整句子、历史对白、文字速度、键盘操作与减少动画选项；检查窄屏和长对白可用性。
- 生成失败保留玩家输入，说明原因并提供对应恢复入口；未配置或失效密钥、额度、网络及非法输出不能伪装成成功剧情。
- 故事库按局保存会话凭据、当前位置和未完成任务，关闭浏览器或重启后仍可继续；API Key 不进入这些存储。后端重启后继续生成须重填密钥，旧节点和已有素材仍可读取。
- 新状态及故事设定带版本；旧节点和批准渲染不重写，旧故事保留兼容路径回放。

## 3. 玩家流程与验收

1. 无密钥时可进入内置 Demo。已有固定世界流程继续可回放；自定义故事入口在对应功能验收后开放。
2. 玩家选择背景、年代和已开放模型，等待设定检查，阅读无剧透简介并确认。批准设定固定后生成八张图片，完整准备结束才进入游玩。
3. 玩家在同一地点调查、交流或出示证据，也可明确移动。行动后立即显示进度；结构、规则校验及事务提交前不展示候选正文。
4. 合法行动提交不可变节点、结构化状态和批准内容；无效、重复及不成立的行动给出具体反馈，不推进地点或发放线索。
5. 玩家从任意非结局节点探索新分支；旧节点回放使用保存的原文、状态与素材，不调用生成器。兄弟分支事件不进入新分支上下文。
6. 断线后继续读取同一任务和缺失事件；同一幂等键不创建第二个任务或节点。关闭浏览器后可从故事库恢复位置、任务与所需会话凭据。
7. 服务重启不会自动重调第三方模型。未完成任务明确标记中断，玩家可显式恢复；图片仅补缺项。失败不留下半个剧情节点，已批准设定及已完成素材保留。
8. 调查证据及进度满足确定性条件后进入最终抉择；三个结局均有可验证路径且后果不同，不通过硬倒计时强制结束。

## 4. 质量与交付门槛

- 固定设定、确定性规则、父状态及祖先已提交事件是事实来源。生成与审核只提出建议，所有状态修改经过现有统一更新路径。
- 覆盖规则、结局可达性、跨故事授权、分支隔离、真实并发幂等、断线补发、重启、图片恢复及并行预算保护；隐藏真相与未发现线索不能泄露到玩家接口。
- 至少验收古代、近现代、未来三种背景的创建和完整游玩，检查调查公平性、角色可信度、行动反馈及配图年代匹配。
- 开局以一分钟左右为优化目标；普通行动通常 10–20 秒、p95 不超过 60 秒。按实测报告，未达标继续优化，不把目标写成已达成结果。
- 便携包包含 Python 运行时、静态前端与 PostgreSQL；干净 Windows 环境无需开发工具即可启动，Demo 离线可玩。独立数据目录、端口检查、迁移及正常停止均须验收，发布包不携带用户数据或密钥。
- 求职展示基于可追溯证据。冻结故事、父状态、行动、模型及上下文，以至少 30 组配对案例比较普通流水线与多 Agent，记录首次输出合法率、回退率、事实冲突、时延、用量和费用；用户按统一评分表参与人工评价，报告标明一位评审。
- 不预设多 Agent 一定优于基线，收益与代价如实记录。未验收时以“可回放互动叙事引擎”描述已有能力；Demo 文本不计入 AI 质量评测。
- 应用中供模型调用的工具及外部服务调用必须独立注册、严格校验并统一处理异常；按调用的安全性设置有限退避重试、总超时及明确失败/降级，不能通过未受控循环绕过状态校验和预算。
- 成功及失败执行均留下可复盘的脱敏 Trace，覆盖各次尝试、校验、耗时、用量与结果，并关联任务、节点及调用费用；失败记录不能随剧情事务回滚丢失。Trace 不保存密钥、会话令牌或隐藏模型思考，也不得向玩家泄露故事秘密。
- 阶段 1 必须交付最小任务成功率评测入口，记录固定案例总数、成功数及失败明细；规则、模拟故障和真实模型评测分开报告。后续模型/工具接入须覆盖调用失败、格式错误、超时与重试耗尽，不能只验收顺利路径。细则见[基础任务评测](evaluation/task-success-baseline.md)。

## 5. 不做事项与完成定义

本轮不加入账号、多用户、云部署、开放世界扩展、pgvector、Redis、配音、存档导入导出、直播、实时视频生成、每日摘要或任意模型 ID。动态图像与阶段 6 多 Agent 已进入计划范围，不能沿用旧文档将它们整体排除。

每阶段按“更新规范 → 实现 → 测试 → 本地验收 → 开发日志 → 相关提交”推进，实际验收通过才标记完成。阶段 0 仅更新文档基线，不代表自定义故事、图片、便携包、OpenAI 或多 Agent 已实现。当前阶段及历史记录见[开发与验收](03-development-plan.md)。
